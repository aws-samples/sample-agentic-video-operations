# Fixtures

Recorded-style AWS responses for `DEMO=1` and the offline tests (write_safe_tools.md §4).
`fixtures/<scenario>/<service>.<operation>.json` answers `client.<operation>(...)`.
A `{"sequence": [...]}` file answers successive calls in order, and the last answer repeats.

All identifiers are placeholders: account `111122223333`, channel `1234567`, `demo-*` names.
The responses are synthetic, built in the shape of the real AWS API responses. Replace them
with sanitized recordings when those are available.

| Scenario | Story | Used by |
|---|---|---|
| `cmcd_rebuffering` | CMCD sessions show bitrate and buffer problems concentrated in one region and CDN | cmcd |
| `frozen_output` | MediaLive pipeline 0 repeats a frozen picture while pipeline 1 keeps moving; encoder telemetry confirms the freeze | medialive, hub |
| `input_loss` | MediaLive pipeline 0 stops receiving its SRT input; the channel stays RUNNING and outputs slate | medialive, hub |

| `srt_packet_loss` | An ACTIVE MediaConnect source stays connected while packet loss and recovery rise; the downstream MediaLive channel sees intermittent input loss. The source thumbnails keep moving (generated by `scripts/generate_quality_fixtures.py`) | mediaconnect, medialive, hub |
| `transport_freeze` | A MediaConnect flow's SRT source stays connected while its picture is frozen; content quality analysis reports frozen frames; generated by `scripts/generate_quality_fixtures.py` | mediaconnect, hub |
| `hls_clean_vod` | A healthy encrypted VOD HLS presentation: 3 ABR variants, I-frame playlist, alternate audio, subtitles, captions, AES-128 key | hls-doctor |
| `hls_missing_variant` | `hls_clean_vod` with the 480p variant playlist returning 404 (mutation `hls_missing_variant`) | hls-doctor |

The `hls_*` scenarios replay HTTP exchanges (`http.exchanges.json`) instead of AWS
responses: each URL maps to a recorded response or an ordered `sequence`. The clean
base is synthetic, authored in the shape of a recorded presentation on the placeholder
host `demo.example`; the broken scenarios derive from it through the deterministic
mutations in `scripts/hls_fixture_mutations.py`, and `scripts/record_hls_fixtures.py`
records replacement bases from a licensed live stream with hosts and query tokens
redacted.
